# AirPlay → DLNA 本地桥接

无需米家账号。MiCast 接收手机的 AirPlay 音频，再通过局域网 HTTP 流和 DLNA 控制命令交给真实播放设备。

## 添加设备

1. 打开“播放”页的“局域网设备”，点击“开启并发现”。MiCast 与设备应在同一网络，设备必须提供 DLNA 播放服务。
2. 找到设备，点击“添加 AirPlay 入口”，输入手机中显示的名称。
3. 可以先测试提示音或持续流。测试会让设备发声，不改变设备音量，随时可以停止。
4. 创建后，在手机 AirPlay 列表中选择该入口播放。

首次设置也可选择“局域网 DLNA 设备”，直接完成设置，无需扫码登录米家。之后仍可连接米家，两类设备能够共存。

桥接入口仅广播 AirPlay，不会额外创建虚拟 DLNA 入口。真实设备自己的 DLNA 入口继续使用。支持 AirPlay 2 的部署可在对应设置中选择 DLNA 目标；仅支持固定 AirPlay 2 入口的安装方式会使用这个入口，更换设备会替换其目标。

## 配置与状态

入口按设备 UDN 绑定，设备名称和型号保存在本地。MiCast 重启、设备短暂离线、地址变化或米家账号切换不会删除本地映射。发现到相同 UDN 时会更新控制地址。

“目标离线”表示当前没有发现在线设备；“发现已暂停”表示网络发现关闭。关闭网络发现会停止网络目标播放，配置仍保留，重新开启后可以继续使用。

可在播放页编辑名称、更换在线目标、隐藏或删除入口。单实例 AirPlay 2 入口通过全局 AirPlay 2 开关显示/隐藏，固定入口不能删除。

## 测试的含义

发现 DLNA、设备接受命令、实际获取音频、实际出声是不同步骤。提示音测试检查是否拉取短音频；持续流测试检查一段流是否传输，仍需亲耳确认出声。某些设备只支持有限文件或特定编码，测试结果不保证所有音频设置或长期播放都兼容。

实际桥接继续使用当前编码与音量设置。没有 DLNA 设备音量控制时，直接映射改用音频流增益。暂停/恢复和停止通过现有播放会话管理处理，旧会话不会停止已被新入口接管的设备。

并非所有小爱音箱都支持 DLNA。未发现设备时先检查设备能力、网络隔离和组播环境。本地链路减少云端控制请求，但 AirPlay 缓冲、编码和音箱解码仍影响延迟，应以实际播放测量为准。


## 能力记录和控制策略（0.3.4）

播放页新增“设备能力与控制通道”。读取已有发现结果和米家缓存，不会为了展示能力请求登录或查询云端设备。声明、命令成功、音频传输、用户确认出声分别显示；未知动作显示未知，离线不会记为不支持。

能力记录保存在配置目录的 capabilities.json。记录区分设备、动作和编码格式，型号或已知固件变化会清除旧证据；确认出声记录超过 30 天不再用于自动优先本地。请在实际听到声音后点击“已听到声音”，确认只能对应最近 24 小时内仍有效的取流记录。

米家单音箱入口可选择“沿用原配置”“已验证时优先本地”“仅本地”“仅云端”。需要用户明确关联对应 DLNA 设备，不按名称或 IP 自动配对。修改前请停止该入口播放。自动模式只在会话开始时为当前音频格式选择通道；仅本地失败不会切回云端，其他入口仍可能使用米家账号。更换目标会清除旧关联。

直接 DLNA 桥接始终使用本地通道。已确认格式在取流中断后最多自动重试两次，每次先成功停止旧播放；停止、暂停或被新会话接管后不再重发。未知格式或控制超时不会自动重复下发。页面显示失败阶段并提供手动重试，需要当前播放仍有效、目标仍归此入口所有且设备在线。

控制响应、首次 HTTP 取流和首次音频字节以毫秒显示，均不代表实际首声延迟。WAV 测试成功不能证明 MP3/FLAC 或长期 AirPlay 流播放成功；默认缓冲与编码参数保持原设置。miIO URL 播放尚未接入自动选路。
