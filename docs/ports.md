# MiCast 端口配置

默认值使用高位端口降低常见服务冲突概率；实际可用性由绑定结果确认。

| 用途 | 默认 | 分配与冲突处理 |
| --- | --- | --- |
| 管理 HTTP/API/WebSocket | TCP 42300 | 首选及后续 32 个候选；先持有已绑定 socket，再交给服务。手填和真正环境变量的数字值严格固定，auto 允许避让。 |
| 音频 HTTP、媒体代理、诊断音频 | TCP 42400 | 与管理 HTTP 共用分配器；实际端口进入流地址。热修改失败可回滚。 |
| 飞牛管理入口 | Unix socket | 由平台网关提供；不受可选 DLNA TCP 监听失败影响。 |
| 飞牛 DLNA 控制 HTTP | TCP 42300 起 | 独立可选监听，支持改端口、失败后重试；失败不公告 DLNA。 |
| 原生 AirPlay RTSP | TCP 42500–42531 | 每入口一个端口，实际绑定时跳过冲突；设置含义是池起点。实际值通过 mDNS 公告。 |
| 原生 AirPlay 接收 UDP | UDP 42600–42795 | 连续三端口组，默认 65 组；部分失败全部释放。范围截到 65535，池起点最多 65533。单次 SETUP 最多尝试 6 组。启动时先确认至少一个完整组，避免公告无法接收的入口。 |
| AirPlay 2 服务控制入口 | 固定 TCP 7000 | 当前 Shairport 接收器启动时会重设端口；飞牛与接收容器均按实际固定端口检查，不扫描替代端口。冲突仅使 AirPlay 2 受阻，释放后可重新启动。飞牛核对监听 socket 属于当前接收进程后才报告就绪。 |
| 接收容器 PCM | TCP 42800 | 独立容器内部端点，控制器需要稳定知道地址；冲突使该实例失败，不任意改号。飞牛本地管道不使用此端口。 |
| 多实例编排器 | TCP 42900 | 内部网络固定端点，无默认宿主机发布。 |
| mDNS | UDP 5353 | 协议端口，共享绑定与组播；不把已有监听当作必然冲突。失败影响依赖该发现的功能。 |
| DLNA SSDP | UDP 1900 | 共享组播端口；实际绑定/入组失败仅使 DLNA 受阻。 |
| NQPTP 时钟与内部接口 | UDP 319、320、9000 | 运行时固定依赖；预检检查绑定，飞牛安装回调以应用身份验证权限/运行库。不可用仅影响对应 AirPlay 2 引擎。 |
| AirPlay 2 媒体会话 | 引擎动态分配 | shairport-sync 协商，不等同于单个 7000 控制端口。 |
| 外部 AirPlay 输出 | 本地 UDP 端口 0；对端公告/SETUP 端口 | 本地由系统分配，远端按真实协商使用；缺失 RTSP 公告时保留旧 TCP 5000 回退。 |
| 外部 URL、米家云、DLNA 回调 | 对端 URL 声明 | 出站连接，不能擅自改对端端口。 |
| Vite 开发/预览 | TCP 42380/42390 | Vite 自行避让；浏览器测试使用端口 0。 |

TCP 与 UDP 同号不构成同一种资源；不同容器 IP 和网络命名空间也不能合并判断冲突。自动选端口不扫描常见低位服务区；手动池起点属于用户选择。

## 统一政策

安装预检以“核心可用且至少一种投送协议可用”为门槛。可选协议失败后保留管理入口、原因及重试能力。用户关闭与故障受阻分开记录；重试不擅自启用关闭的功能。

`.env` 数字默认保持原有首选值语义；应用设置手填的单监听端口、真正环境变量数字值严格固定。环境变量可填写 auto。旧持久化自定义值迁移为手动策略，数值本身不改；飞牛旧 AirPlay 2 端口配置例外，迁移到接收器实际固定的 7000。RTSP/UDP 始终是池起点，在池内分配。

进程内 HTTP 服务持有绑定资源，避免先检测、关闭、再绑定的竞争窗口。安装到启动之间、外部引擎启动、Docker 发布映射仍需要实际运行再次验证，预检结果不是永久占用。

Docker classic 默认自动分配，健康检查读取实际管理端口。single/multi 的内部回调仍访问控制器 42300；宿主机映射由宿主机规划程序检查，音频映射使用相同内外端口。桥接控制器不声明原生 AirPlay/DLNA 接收能力，独立接收器负责局域网公告。

正式启动入口为 python -m micast，Windows 可执行程序使用同一启动机制。直接调用 uvicorn 的管理监听属于其命令行控制，无法由应用自动改变。

安装方式与启动命令见 [部署说明](deployment.md)。

协议参考：[NQPTP 官方说明](https://github.com/mikebrady/nqptp)、[Shairport Sync 官方配置](https://github.com/mikebrady/shairport-sync/blob/master/scripts/shairport-sync.conf)。
